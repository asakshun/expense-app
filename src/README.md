# 支出管理アプリ - プロジェクト構造

このプロジェクトはクリーンアーキテクチャの原則に従って構成されています。

## ディレクトリ構造

```
src/
├── domain/                    # エンティティ層（最も内側）
│   ├── entities/             # ドメインエンティティ
│   └── value-objects/        # 値オブジェクト
│
├── application/              # ユースケース層
│   ├── use-cases/           # ユースケース実装
│   └── repositories/        # リポジトリインターフェース（ポート）
│
├── infrastructure/           # インフラストラクチャ層
│   └── gateways/            # リポジトリ実装（アダプター）
│
└── presentation/             # プレゼンテーション層（最も外側）
    ├── controllers/         # HTTPコントローラー
    └── presenters/          # プレゼンター
```

## 依存関係の規則

1. **依存関係の方向**: 外側の層は内側の層に依存できるが、内側の層は外側の層を知らない
2. **依存性逆転の原則**: ユースケース層はリポジトリインターフェース（ポート）を定義し、外側の層がそれを実装（アダプター）
3. **エンティティの独立性**: エンティティ層は他のすべての層から独立

## テスト戦略

- **ユニットテスト**: 特定の例、エッジケース、エラー条件を検証
- **プロパティベーステスト**: すべての入力に対する普遍的なプロパティを検証（fast-checkを使用）

テストファイルは実装ファイルと同じディレクトリに配置し、`.test.ts`または`.spec.ts`の拡張子を使用します。
